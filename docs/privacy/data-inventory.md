## Account deletion evidence and limits

On 2026-08-21, a disposable staging identity completed the public API workflow on its first worker attempt. Supabase Auth identity deletion, PostgreSQL anonymization, and profile/listing Storage cleanup passed, the demo identity remained intact, and no incomplete or failed request remained. `ACCOUNT_DELETION_ENABLED` was restored to `false`; the public unauthenticated instructions remain at the configured Vercel `/account-deletion` page.

The application worker cannot erase hosting logs, provider security logs, managed backups, build artifacts, or data retained under a future legal hold. Those provider workflows and retention periods require owner/legal approval. Do not run the destructive drill against a real tester merely to repeat evidence.

## Data export decision

A self-service export is deferred for closed beta: it is not currently a store gate, and a rushed export risks exposing private counterparty, moderation, and transaction data. Before public launch, legal/product must define scope and identity verification, then implement a bounded asynchronous export if required.

## Client-owned approvals

Before invited beta or store submission, the client and legal owners must approve retention/legal bases for commerce, safety, audits, provider logs/backups, and dispute evidence; verify provider DPAs and access roles; supply Privacy Policy, Terms, Community Guidelines, and support URLs; and approve exact Apple/Google declarations. Re-review this inventory whenever a disabled provider is enabled. Do not paste it into a store form without confirming the deployed behavior and provider consoles.
